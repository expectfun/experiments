Add the distances of every road travelled. The optimal route has the lowest total cost.

20 cities, 23 roads. Traffic, fuel and weather are left out. The model is known, deterministic and fully observable.

What is the algorithm remembering?

The frontier is a priority queue of candidate path nodes. The reached table maps each city to its cheapest path found so far. It includes both frontier and expanded states.

A state is a city. A node also stores its parent, action and accumulated cost. Two nodes can represent the same city via different routes.

Why reject a path? (§ 3.3.3)

Returning from Sibiu to Arad costs 280, but we already reached Arad at cost 0. Reject that cycle. Likewise, Arad → Zerind → Oradea → Sibiu costs 297, worse than the direct road at 140.

A cheaper alternative is different: update reached and add the new node. This lab follows Figure 3.7 literally: an older, worse queue entry is retained and labelled “older path.”

Choosing f(n): what “best” means

Section 3.3 gives a general framework; the evaluation function decides which path comes next. This lab offers two concrete examples:

  • Path cost: choose the least distance travelled so far. This is uniform-cost search (developed in § 3.4). On this finite network with positive road costs, it finds a minimum-cost route.
  • Depth: choose the fewest roads so far. This orders nodes by depth; it is not the optimized breadth-first implementation of § 3.4. It keeps Figure 3.7’s cost-based reached test and tests the goal when a node is removed. Fewer roads need not mean fewer miles.

Finding a goal among the children does not end this algorithm. It returns a goal only when that node is removed from the frontier.

How to judge a search (§ 3.3.4)
  • Completeness: will it find a solution if one exists? Both settings finish on this finite, positive-cost network.
  • Cost optimality: is the returned route cheapest? The cost setting guarantees this here; depth does not.
  • Time: expansions and generated nodes reveal search effort, not elapsed animation time.
  • Space: peak frontier measures queue occupancy only. The reached table also uses memory; this teaching page additionally stores rejected nodes and history for replay.

For implicit state spaces, the book uses branching factor b, solution depth d, and maximum path depth m to describe complexity.
